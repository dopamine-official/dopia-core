# frontend

대만을 첫 대상으로 하는 캐릭터 채팅의 로컬 프로토타입입니다. 한국어(`ko-KR`), 대만 번체 중국어(`zh-TW`), 영어(`en-US`)를 지원합니다. 이 문서의 파일 경로는 `frontend/` 기준입니다.

## 실행

Node.js 20.9 이상이 필요합니다. 현재 폴더에는 실행에 필요한 의존성이 준비되어 있습니다. 아래 명령은 `frontend/` 또는 저장소 루트에서 실행할 수 있습니다.

```bash
npm run dev
```

브라우저에서 <http://127.0.0.1:3000>을 엽니다. 포트가 이미 사용 중이면 터미널에 표시된 주소를 사용합니다. 폴더 이동 전에 실행한 서버는 종료하고 다시 실행합니다.

새로 내려받은 환경에서는 저장소 루트에서 설치합니다.

```bash
npx pnpm@10.28.2 install --frozen-lockfile
npm run dev
```

환경변수, API 키, 외부 서비스 계정은 필요하지 않습니다. 현재 환경의 npm 네트워크 제한 때문에 기존 로컬 패키지의 동일 버전을 작업 폴더로 복사해 검증했습니다. 프로젝트 코드에는 해당 외부 폴더 경로에 대한 의존성이 없습니다.

## 구현 범위

- 홈의 캐릭터 카드, 배너, 최근 대화, 반응형 사이드바
- 게스트 식별, Google/Apple별 모의 로그인, 로그인 시 게스트 대화 이관
- 프로필 닉네임·사진 수정, 로그아웃, 탈퇴
- 캐릭터별 대화방, 준비된 응답의 SSE 스트리밍
- 전송 중 새 초안 작성, 한글 조합 입력, 행동 묘사, 스크롤 따라가기
- 중복 전송 방지, 실패한 입력 복구, 스트림 끊김 뒤 조회, 새로고침 뒤 응답 복구
- 로컬 저장, 테스트 데이터 초기화, 정상·빈 목록·오류·느린 응답 시나리오
- 세 언어 번들, 언어별 캐릭터 콘텐츠, 날짜·숫자 표기, 번역 키 검사

외부 LLM, OAuth, 결제, Supabase, PostHog, Langfuse를 호출하지 않습니다. 크레딧 영역·충전·턴 제한을 제외했습니다. 성인 캐릭터에는 비노골적인 예시 대화만 있습니다. 게스트와 신규 회원은 SAFE ON(`adult_mode: false`, `adult_verified: false`)으로 시작합니다. 게스트가 SAFE를 누르면 로그인으로 이동하고, 미인증 회원에게는 인증 필요 안내만 표시합니다. 인증된 회원만 SAFE 변경 API를 호출할 수 있고, 모의 API도 같은 조건을 검사합니다. 실제 성인 인증 절차는 아직 구현하지 않았으므로 일반 모의 로그인만으로 SAFE를 끌 수 없습니다. 이전 미리보기에서 저장한 게스트·미인증 계정의 SAFE OFF 값은 계정 조회 시 ON으로 보정하며 대화는 유지합니다.

## 화면 확인

1. 홈에서 캐릭터를 선택하고 메시지를 전송합니다.
2. 상단에서 언어를 변경합니다. UI와 이후 응답의 언어가 바뀌고 기존 대화 원문은 유지됩니다.
3. 채팅 중 로그인한 뒤 같은 방에 돌아와 대화가 이어지는지 확인합니다.
4. 마이페이지에서 프로필을 수정하고 새로고침합니다.
5. 홈 하단의 **미리보기 설정**(`/preview`)에서 응답 실패·스트림 끊김·느린 응답을 선택합니다.
6. 미리보기 설정에서 빈 홈과 조회 실패를 확인하거나 테스트 데이터를 초기화합니다.

실패와 스트림 끊김, 홈 조회 실패는 한 번만 적용됩니다. 홈의 일시적인 조회 실패는 자동 재시도로 복구됩니다. 느린 응답·빈 목록은 설정을 바꿀 때까지 유지됩니다. 삭제·초기화는 확인 창 뒤에 실행됩니다.

## 언어 설정

`src/i18n/deployment.json`의 `profile`로 노출 언어를 선택합니다.

지역 목록과 기본값은 `src/i18n/regions/index.json`의 `default_region`, `default_locale`, `regions`에 있습니다. `regions/TW.json`은 `code`, `enabled`, `locale.default`, `locale.supported` 구조로 대만 배포 언어를 정의합니다. 개발 중 한국어를 추가하는 설정은 별도 `profiles.json`에 두고, 코드는 `regionConfig()`로 합쳐진 설정을 읽습니다. 가입 연령·법적 문서·운영 데이터 보존 정책은 이번 프로토타입에서 설정하지 않습니다.

| profile       | 기본 언어 | 지원 언어               |
| ------------- | --------- | ----------------------- |
| `development` | 한국어    | 한국어, 대만 번체, 영어 |
| `taiwan`      | 대만 번체 | 대만 번체, 영어         |

대만 배포용 언어 설정:

```json
{ "region": "TW", "profile": "taiwan" }
```

국가와 언어는 별개입니다. 국가는 두 설정 모두 TW입니다. 저장된 한국어 선택값은 `taiwan` 설정에서 대만 번체로 돌아갑니다. 한국어 번역 파일은 삭제할 필요가 없습니다. 이 설정은 언어 노출만 바꾸며, 실제 인증·AI·서버 연결은 별도 구현 대상입니다.

UI 문구는 `src/i18n/locales/<locale>/<namespace>.json`, 캐릭터 콘텐츠는 `src/mocks/characters.ts`에 있습니다. 사용 중인 번들은 일반 문자열과 `{name}` 같은 매개변수를 지원하며, 복수형 ICU 구문은 이번 프로토타입에서 사용하지 않습니다.

## 구조와 API 경계

```text
src/app/              Next.js App Router 페이지
src/components/       홈, 로그인, 프로필, 채팅, 미리보기 설정
src/lib/api.ts        요청 헤더·오류 처리·SSE 해석
src/lib/contracts.ts  요청/응답 Zod 스키마
src/mocks/            HTTP 모의 API, 상태 처리, IndexedDB 저장소
src/i18n/             공통 언어 해석과 지역 설정, 번들
tests/                계약 테스트와 브라우저 흐름 테스트
```

화면은 `/api/v1/...` 요청과 명세의 JSON/SSE 계약을 사용합니다. MSW가 브라우저에서 요청을 처리하고 IndexedDB에 데이터를 저장합니다. 이후 `api.ts`와 초기화 부분에서 실제 서버로 연결할 수 있습니다. API 명세 출처는 별도 저장소의 `test-chat-spec/DOMAIN`입니다. 이미지와 배치의 원본은 그 저장소의 `REFERENCE/SCREEN`입니다. 스펙 원본은 이 모노레포에 포함하지 않습니다.

| 경로                                       | 동작                                          |
| ------------------------------------------ | --------------------------------------------- |
| `POST /api/v1/account/guest`               | 게스트 생성 또는 기존 사용자 ID 반환          |
| `GET/PATCH /api/v1/account/me`             | 프로필 조회/수정                              |
| `PATCH /api/v1/account/me/adult_mode`      | 성인 인증된 회원의 SAFE 변경                  |
| `POST /api/v1/account/logout`, `/withdraw` | 로그아웃/탈퇴 후 새 게스트 ID 반환            |
| `GET /api/v1/home`                         | 지역화된 홈 목록                              |
| `POST /api/v1/chats/open`                  | 기존 방 열기 또는 새 방 생성                  |
| `GET /api/v1/chats/recent`                 | 최근 대화                                     |
| `GET/DELETE /api/v1/chats/:room_id`        | 대화 조회/논리 삭제                           |
| `POST /api/v1/chats/:room_id/messages`     | `accepted`, `token`, `completed`/`failed` SSE |
| `/api/v1/mock/*`                           | 모의 로그인, 시나리오, 초기화, 로컬 이벤트    |

실제 OAuth 리다이렉트·콜백 대신 `POST /api/v1/mock/login`을 사용합니다. 모의 요청 식별은 IndexedDB의 활성 계정과 `X-Preview-Account` 검증으로 구현했으며 HttpOnly 인증 쿠키를 구현한 것은 아닙니다. 일반 계약의 `X-Locale`, `X-Region`은 그대로 사용합니다. 모의 API가 시작되지 않은 직접 서버 호출에는 503이 반환됩니다.

게스트 발급·로그아웃·탈퇴 응답은 `{ "account_id": "…" }`만 반환하며, 화면은 그 ID로 `GET /api/v1/account/me`를 호출해 전체 프로필을 받습니다. 일반 요청의 401은 게스트 발급과 내 정보 조회로 복구합니다. 같은 계정이면 원래 요청의 본문·전송 ID를 유지해 한 번만 재요청하고 화면과 초안을 유지합니다. 동시 401은 복구 요청을 공유하며, 복구 실패·계정 변경·요청 취소 시 원래 요청을 재전송하지 않습니다. 계정이 바뀐 뒤 도착하는 이전 요청의 응답도 반영하지 않습니다.

GET 조회와 게스트 발급은 네트워크 오류·5xx에 한 번만 자동 재시도합니다. 그 뒤에도 실패하면 해당 영역의 안내와 다시 불러오기 버튼을 표시합니다. 4xx는 기존 401 복구를 제외하면 자동 반복하지 않습니다. 프로필 저장·SAFE 변경·방 열기·전송·삭제·로그아웃·탈퇴도 5xx나 네트워크 오류만으로 자동 반복하지 않습니다. 오류 안내는 연결 상태, 서버 오류, 인증·권한, 입력 필드, 사진 크기, 생성 중인 답변 등을 구분하며 세 언어로 제공합니다.

로그아웃과 탈퇴의 홈 이동은 계정 교체로 인한 페이지 재마운트에도 유지됩니다. 모달은 Escape·닫기·바깥 클릭 등으로 닫히면 연결되어 있는 원래 버튼으로 초점을 돌려줍니다. 카드나 배너로 방을 여는 동안 다른 카드도 잠기며, 최근 대화를 선택하거나 홈을 떠나면 진행 중인 열기를 취소하고 늦은 응답의 이동을 무시합니다.

## 데이터 수명과 명세 차이

- 계정·프로필 사진·대화: 같은 브라우저/주소의 IndexedDB. 다른 기기와 동기화하지 않습니다.
- 언어 선택: localStorage. 작성 중인 글과 미확정 전송: 계정·방별 sessionStorage.
- 로그아웃은 새 게스트로 전환하며 회원 데이터는 남깁니다. 같은 제공사로 다시 로그인하면 복구됩니다.
- 탈퇴는 해당 모의 회원과 소유 대화를 로컬에서 삭제합니다. 전체 초기화는 이 앱의 데이터만 지웁니다.
- 한 IndexedDB 트랜잭션 안에서 방 생성·전송·계정 이관을 처리합니다.
- 가짜 생성의 결과·완료 시각을 저장합니다. 탭을 닫아도 다음 조회가 완료 시각을 기준으로 상태를 확정합니다. 서버의 실제 백그라운드 작업은 아닙니다.
- 이벤트는 메시지 본문 없이 최근 100건을 브라우저에만 저장합니다. 실제 분석 도구에는 전송하지 않습니다.
- 프로필 사진 상한 2MB, 일반 응답 약 2.2초, 느린 응답 약 6.5초는 프로토타입용 값입니다.
- 브라우저 저장소를 사용하므로 사용자별 데이터는 초기 클라이언트 로드 후 표시합니다. 실제 서버 인증·SSR, 운영용 보존 정책, Spring/FastAPI 서비스, 배포는 이번 범위에서 제외합니다.

## 검사

```bash
npm run check        # 세 언어 키·매개변수 일치, TypeScript, 계약 테스트
npm run build        # 프로덕션 번들 생성
npm run test:e2e     # 데스크톱/모바일 사용자 흐름
```

브라우저가 설치되지 않은 새 환경에서는 저장소 루트에서 `npx pnpm@10.28.2 --dir frontend exec playwright install chromium`을 먼저 실행합니다. E2E는 기존 3000 포트 서버가 있으면 재사용하고, 없으면 시작합니다. 브라우저 서비스 워커와 IndexedDB를 사용하므로 실행 주소는 localhost 또는 HTTPS여야 합니다.

계약·HTTP·SSE·401 복구·재시도·오류 안내 테스트는 89개, 데스크톱·모바일 E2E는 26개입니다. E2E에는 로그아웃·탈퇴 후 홈 이동, 모달 초점 복귀, 카드 잠금과 늦은 응답 무시, 자동·수동 재시도, 프로필 오류 안내를 포함합니다. 이번 작업 환경에서는 서버 포트 열기가 `EPERM`으로 거부되어 E2E 실행을 완료하지 못했습니다. E2E 실행에는 로컬 개발 서버와 브라우저 연결이 필요합니다.
